02 · The big picture

The hexagon: engine in the middle, adapters at the edges

StageArtifact(order, slug, label, image) is the emission contract: the pipeline yields one per stage, both frontends consume the same stream. repository.py and artifacts.py live inside sams_core/ but face outward as driven adapters.

The registry is the single source of truth

  • Names, slugs, and order are defined exactly once in pipeline.py, glossary-verbatim — CLI and Web UI can never disagree on the stage list.
  • Processing is a generator (or callback-fed runner) yielding StageArtifact per stage — exactly 7, one each.
  • Per-cell inspection emits one composite overlay image, not one artifact per cell.
  • Stages are pure functions: ndarray in, ndarray out — that purity is our unit-test seam (AD-9).

The emission contract: display-ready RGB uint8

  • StageArtifact.image is display-ready uint8: 2D grayscale or 3-channel RGB.
  • Adapters own toolkit conversion: CLI converts RGB→BGR for cv2.imshow; artifacts.py converts for cv2.imwrite; st.image consumes RGB as-is.
  • CLI stage windows are shown live during processing, each titled with its stage name — saving alone does not satisfy FR-11.
  • Signature crops are not StageArtifacts — they flow through artifacts.py separately (AD-10).

04 · The one entry point (AD-12)

process_sheet() — and why nobody else persists

# the ONE call both frontends make — sams.py and the Web Process page process_sheet(image_path/bytes, info_file, sheet_id_override=None, overwrite=False) -> SheetResult

What it does

  • Runs the full 7-stage pipeline.
  • Persists results internally on success, via the repository.
  • Returns a SheetResult (including warnings).

Stage emission is a side channel

  • StageArtifacts stream out via generator/callback while it runs.
  • Partial iteration or abort never persists — no half-processed sheets in the DB.

Why this rule exists

  • If frontends decided who persists, they would disagree — and Web-processed sheets would be silently unsaved.
  • One entry point means CLI-vs-Web parity at the data layer is automatic.

Overwrite semantics: operator resolutions survive re-processing unless overwrite=True is passed explicitly — CLI --overwrite flag, Web UI confirm dialog (AD-4).

05 · Data contracts (AD-2)

models.py: frozen dataclasses or it doesn't cross a boundary

Cross-boundary data passes only as frozen dataclasses + enums from sams_core/models.py. No module defines its own cross-boundary shape — no bare dicts or tuples between 10 authors.

AttendanceStatus

Enum: PRESENT / ABSENT / AMBIGUOUS. Ambiguous is a first-class persisted status, not an error.

StageArtifact

order: int, slug: str, label: str, image: ndarray — image display-ready uint8, grayscale or RGB.

SheetResult

Returned by process_sheet(). Includes warnings: list[str] — non-fatal anomalies (e.g. row-count mismatch); processing still completes.

StudentRecord & AttendanceRecord

AttendanceRecord carries session/subject metadata alongside the status.

ReferenceScore

reference_path, score: float in 0–1 — higher = more similar, always (distance metrics are normalized/inverted inside verification.py).

VerificationResult

best: ReferenceScore, all_scores: list[ReferenceScore], matched: bool, threshold: float. Multi-reference comparison and best-match selection live in the engine; matched = score >= threshold. Frontends only render.

06 · The rules that keep us compatible

Twelve decisions. Break one, break a teammate.

AD-1

Ports & Adapters boundary

All new logic lives in sams_core/; entry scripts & pages stay thin (<50 lines); the core never imports a UI framework.

AD-2

Data contracts in models.py

Cross-boundary data moves only as frozen dataclasses + enums defined in models.py.

AD-3

One canonical pipeline registry

The 7 stages — names, slugs, order — are defined exactly once in pipeline.py; stages are pure ndarray→ndarray functions.

AD-4

Single DB gateway

repository.py is the only sqlite3 importer; upserts keyed (Student Index, Sheet Identifier); operator resolutions survive unless overwrite=True.

AD-5

Config ownership

Every tunable is a named constant in config.py — no numeric literals in stage/verification code, no per-sheet special-casing.

AD-6

Error strategy

Exceptions only for cannot-proceed; anomalies become SheetResult.warnings; unknown/no-data cases are results, never exceptions.

AD-7

Display boundary

The core never shows UI; visualization.py returns Figures; adapters render (CLI windows / st.image).

AD-8

Dependency isolation

Core + CLI import only cv2/numpy/matplotlib/sqlite3/stdlib; streamlit exists only in requirements-web.txt + webui/.

AD-9

Testing seam

pytest imports sams_core only; test_accuracy.py makes the SM-1..SM-3 gate executable; match logic lives in verification.py.

AD-10

Signature image ownership

References live at references/<student_index>/; crops saved by artifacts.py; DB stores path metadata, never image blobs.

AD-11

Sheet Identifier resolution

Resolved in the engine before the pipeline: Info File date → operator date → filename stem (CLI only), normalized to ISO 8601.

AD-12

Single engine entry point

process_sheet() is the one call both frontends make; it persists on success — nobody else persists.

07 · Who owns what (AD-4, AD-5, AD-10, AD-11)

Ownership map: one owner per concern

Database — repository.py only

  • The only module that imports sqlite3; schema auto-created (ensure_schema on open); DB path from config.py.
  • Connections are per-operation via context manager — no cached, global, or long-lived connections (Streamlit threads + concurrent CLI safety).
  • Read APIs: list_students(), has_operator_resolutions(sheet_id). Write: resolve(sheet_id, student_index, status, by_operator=True), with undo restoring Ambiguous.
  • Attendance upsert keyed (Student Index, Sheet Identifier); resolutions carry resolved_by_operator.

Tunables — config.py only

  • Ambiguous coverage bands, similarity threshold, binarization/deskew params, DB path, output dir — all named constants; no numeric literals in stage or verification code.
  • SM-C1 anti-overfitting binds here: no hard-coded pixel coordinates, no per-sheet special-casing, no per-image thresholds — all tunables global.
  • All filesystem paths relative to project root (FR-15 portability).

Filesystem contracts

  • references/<student_index>/ — Reference Signatures, pre-populated by the team from sheets 1–3 and committed to the repo; engine only reads + registers metadata.
  • output/<Sheet Identifier>/NN-slug.png — per-sheet stage images, written by artifacts.py.
  • output/<Sheet Identifier>/crops/<student_index>.png — probe crops from per-cell inspection.
  • Both registered as path metadata via repository.py, retrievable by Student Index. No image blobs in the DB.

Index resolver — one, in the engine

  • The canonical 8-digit Student Index is the ONLY key form stored or queried in the Local DB.
  • The short ordinal (e.g. 002) is an input alias, resolved by one engine resolver (models.py or repository) before any read/write.
  • No adapter parses index forms itself — everywhere an index is accepted, both forms resolve.

08 · Errors & no-data (AD-6)

Three channels: exception, warning, no-data — pick the right one

Exceptions — cannot proceed
  • Hierarchy in errors.py: SamsError base; InputError (bad image / Info File); ProcessingError (pipeline failure).
  • The engine raises, never prints/exits/shows UI.
  • CLI translates to one-line stderr + exit codes: 0 ok, 2 input error, 1 other. Success line reports record count + resolved Sheet Identifier.
  • Web UI translates to UX error-catalog strings. No raw stack trace ever reaches the grader.
Warnings — processing completes
  • Non-fatal anomalies go in SheetResult.warnings: list[str] — e.g. row-count mismatch.
  • Never raised as exceptions; the sheet is still processed and persisted.
  • Frontends surface warnings; they don't halt.
No-data — a valid answer
  • Unknown Student Index is not an error: lookup APIs return a no-data result carrying valid indices from list_students().
  • CLI prints a friendly list and exits 0; Web renders the no-data state.
  • Same family: known index but no probe yet; empty/missing references for a known student. Never exceptions.

The PRD §6.3 gate

  • The Web UI is built only after SM-1..SM-3 pass on all 5 sample sheets.
  • The gate is executable, not eyeballed: tests/test_accuracy.py scores against tests/data/ground_truth.csv.
  • ground_truth.csv is committed before threshold tuning; Disputed rows are excluded from SM-1 scoring.
  • Verification evaluation is disjoint: references from sheets 1–3, probes from sheets 4–5 (FR-9/SM-4).
  • Fallback deliverable if the gate never passes: engine + CLI only — the graded surface is safe either way.
